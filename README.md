### 1. 🍽️ 서울시 요식업 폐업 위험 예측

> **"같은 업종이라도, 어느 동네·어떤 상권이냐에 따라 폐업 위험은 다르지 않을까?"**

서울시 상권분석서비스 공개 데이터(2023 Q1 ~ 2025 Q4, 25개 자치구, 요식업 10개 업종)로 폐업 위험을 분석하고 **다음 분기 폐업률을 예측**했습니다. 팀 프로젝트로 진행했고, 그중 **가설 1 (동일 업종이라도 상권 유형·자치구에 따라 폐업 위험이 다르다)** 의 EDA · 통계 검정 · 예측 모델링을 맡았습니다.

**분석 흐름**

```mermaid
flowchart LR
    A[데이터 수집] --> B[품질 검증<br/>지표 공식 · 항등식]
    B --> C[EDA]
    C --> D[통계 검정<br/>Kruskal-Wallis · Dunn]
    D --> E[예측 모델링]
    E --> F[비즈니스 제언]
```

**핵심 결과**

- 10개 업종 중 **한식음식점만 점포 수가 증가(+2.3%)**, 나머지 9개는 감소 — 요식업은 전반적으로 축소 중
- 가설은 지지됐지만 **상권 유형(ε² 0.008~0.087)보다 자치구(ε² 0.050~0.457)가 훨씬 큰 차이**를 만듦. 한식은 폐업률 변동의 절반 가까이를 *"어느 자치구인가"* 가 좌우
- 자치구는 저위험 · 중간 · 고위험 3개 군집으로 구분됨 (Dunn's test)
- 6가지 예측 기법 비교에서 **가장 단순한 Pooled OLS가 1위** — 그룹당 데이터가 11개 분기뿐이라 정교한 모델일수록 과적합
- *이번 분기 개업이 몰린 곳*이 다음 분기 폐업의 유의한 선행 신호. Walk-forward 검증 8개 시점 중 7개에서 R² 양수

**정직한 한계:** 홀드아웃 R² = 0.016으로 절대 예측력은 낮습니다. 소규모 상권은 폐업률이 0% → 100%로 튀어 구조적으로 예측이 어렵다는 점을 확인했고, 이를 근거로 *"점포 30개 미만 상권은 별도 모니터링"* 을 제언했습니다.

**배운 점:** 피처가 많다고 성능이 오르지 않는다는 것, 짧은 기간 안에 결과물을 내려면 범위를 먼저 좁혀야 한다는 것.

### 2. ☕ 스타벅스 오퍼 완료율 요인 분석

> **"같은 오퍼인데, 왜 어떤 오퍼·어떤 고객에게서만 완료율이 높을까?"**

프로모션 로그(오퍼 76,277건 · 고객 17,000명)로 오퍼 설계 요소와 고객 프로필이 완료율에 미치는 영향을 분석했습니다. **가설 트리 → 지표 지도 → 원인 분해 → 통계 검증** 순서로 진행했고, 12개 가설을 검증해 **지지 4 · 부분지지 2 · 보류 2 · 기각 4** 로 정리했습니다. 채택한 지표만 담은 **인터랙티브 대시보드**도 제작했습니다.

**핵심 결과**

- **discount(58.6%) > bogo(51.4%)** — 설계 변수를 보정해도 오퍼 유형 고유의 효과가 유의하게 남음
- **성별 효과가 가장 크고 견고** — 남성 × BOGO 조합이 전체 최저(42.4%)
- **소득이 낮을수록 보상에 민감** — 보상에 따른 완료율 스프레드가 저소득 33.5%p vs 고소득 7.7%p
- 🔄 **반전 발견:** *"고령층은 수신율이 낮을 것"* 이라는 가설은 기각. 약점은 오히려 **청년층**(수신율 격차 27.15%p로 최대)
- 제언: Discount 비중 확대 파일럿, 청년층 채널 Mobile · Social 리밸런싱, 남성 대상 BOGO 재설계 A/B 테스트

**정직한 한계:** 오퍼 수신 없이 발생한 완료가 25.8%여서 완료율을 오퍼의 순수 효과로 단정할 수 없고, 설계 변수가 완전교차 설계가 아니라 효과를 독립적으로 분리하기 어렵습니다. 그래서 **ML 모델은 일부러 적용하지 않고 데이터 보강 후로 보류**했습니다.

**내가 한 일:** 가설 트리 · 지표 지도 · 원인 분해 · 통계 검증 · 대시보드 디자인 · **발표**

### 3. 🏯 궁·능 관람객 예측과 인력 배치

> **"지난 7일 평균으로 다음 14일의 인력을 배치하면, 연휴에는 왜 늘 부족할까?"**

국가유산청 궁능유적본부의 일별 관람객 데이터로 **23개 개소의 14일 앞 방문객을 예측**하고, 부족 비용(60만 원/인·일)이 잉여 비용(15만 원)의 4배라는 점을 반영해 **q80 기준 운영 인력**을 산정했습니다. 최종 산출물은 **2026-01-01~14 개소별 인력 배치표**입니다.

**핵심 결과**

| 구분 | 총비용 |
|---|:---:|
| 현행 방식 (직전 7일 평균) | 15.66억 원 |
| **채택 모델 (Chronos-2 + 공휴일 + 무료개방, q80 운영)** | **8.58억 원 (-45.2%)** |

- 현행 방식은 **연휴 8주(전체 주의 15%)에 손실의 31.8%** 가 집중
- 14개 모델을 2025년 27개 원점 순차 백테스트로 비교 → **WAPE 33.57% → 29.35%** (공휴일 · 무료개방 정보 추가)
- 이웃 궁 휴관 · 외국인 · 행사 정보는 *추가해도 성능 차이가 없어* **반복성 · 사전 확정성 · 재현성**을 갖춘 정보만 입력으로 채택
- 같은 오차라도 부족 비용이 4배라 **평균이 아닌 q80(split conformal)** 으로 배치해야 총비용이 줄어듦

**정직한 한계:** 권고 인원은 실제 근무표가 아니라 *예측 방문객과 운영 가정(2,000명당 1명)으로 계산한 관람객 대응 필요 인원*이며, 비용 가정은 운영팀 확정이 필요합니다.

**내가 한 일:** 데이터 · 피처 담당 (전처리 · 공변량 설계) · 최종 **발표**

### 4. 📞 질병관리청 민원 분석 파이프라인

> **"민원 전화 한 통이 어떤 유형인지, 모델이 신규 민원에도 계속 맞힐 수 있을까?"**

질병관리청 민원 상담 텍스트(17,642통화)로 **민원 유형 분류 · 요약 · 반복 민원 분석**을 수행하고, LLM 분석 성능을 **검증 · 점검할 수 있는 재사용 파이프라인**을 만드는 학업(비상업) 팀 프로젝트입니다. 의뢰사와 판매 시나리오는 가상입니다. 이 중 **LLM 분석과 로컬 LLM 기반 분류 시스템의 설계 · 개발**을 맡았으며, AI 코딩 에이전트와 협업해 구현했습니다.

**접근 방식:** `KURE-v1` 임베딩 + `BERTopic`으로 토픽을 만들고 24개 민원 코드의 **코드북을 v1 → v5까지 다듬어 동결**한 뒤, 골드셋 라벨링과 재배정 평가를 거쳐 **BERTopic + 로컬 LLM(`llama.cpp`)** 구조로 결합했습니다. 외부 전송 없이 로컬 LLM만 사용합니다.

**내가 한 일 — 로컬 LLM 시스템**

- **실행 환경 실측 점검:** GPU(RTX 5070 Laptop 8GB) · RAM · 드라이버 · 설치 패키지를 확인하고, 설치 금지 상태에서는 필요한 항목을 목록으로만 정리
- **실행 방식 비교:** `transformers + bitsandbytes` · `llama.cpp(llama-server)` · `Ollama`를 현 환경 적합성 · 위험 · 비용으로 비교해 **GGUF + llama.cpp 로컬 서버**를 우선 후보로 판정
- **모델 후보 조사와 설계:** 한국어 로컬 모델 후보를 조사하고, 분류 · 요약 결과를 JSON으로 받는 **LLM 분류 · 요약 하네스**와 모니터링 재사용 설계서를 작성. 출처 신뢰도가 낮은 정보는 `미검증`, 확인하지 못한 항목은 `미확인`으로 구분해 표기
- **분류 프로그램:** 실행 시 **PC를 자동 점검**해 환경에 맞는 LLM 프로필(CPU · 8GB)을 선택하는 민원 통화 분류 프로그램의 화면(로딩 · 메인 · 도움말)을 만들고, 화면별로 확인한 뒤 해시를 기록
- **운영 원칙:** 외부 전송 없이 로컬에서만 실행

**프로젝트 전체 결과 (팀)**

- 코드북을 다듬자 코드 일치율이 오름 — 첫 평가 **71.7%** (Wilson 하한 65.6%) → 신규 150건 **77.5%** (Wilson 69.9~83.7), 대분류 일치 **94.9%**
- 라벨 방식이 결과를 가름 — 검토한 건은 일치 56.5%, 검토 없이 수용한 건은 94.7%. 이를 계기로 중간 · 높음 144건을 초안 없이 **다시 라벨링**하기로 결정
- 단계별 동결 해시 · 동일성 검사로 **재현 가능한 파이프라인**(`pipeline.yaml`) 구성

**정직한 한계:** 신규 표본의 Wilson 하한이 기준(70%)보다 0.1%p 낮아 **기준 충족은 아닙니다.** 신규 150건은 골드셋이 아니며, 데이터 반출 제한으로 코드와 문서만 공개합니다. 로컬 LLM 결합 성능 시험은 아직 확정 전이고, 분류 프로그램 화면도 검증 전 단계입니다.

### 🌦️ 기후위기에 흔들리지 않는 서울 생활상권 — 2026 빅콘테스트

> **"기후위기는 상권 전체를 똑같이 위축시키는가, 아니면 특정 시간 · 업종 · 지역에 서로 다른 부담을 만드는가?"**

2026 빅콘테스트 **AI데이터 분석 분야** 참가작입니다. 1981~2025년 장기 기상자료, 대회 제공 카드 결제 · 유동인구 자료(2025.07~12, 강남구 · 춘천시), 서울 상권 · 침수흔적 · 지형자료를 결합해 **기후취약상권을 정의하고 우선점검 기준과 보호정책**을 제안했습니다.

```mermaid
flowchart LR
    A[데이터 수집<br/>카드 · 통신 · 기상 · 상권] --> B[품질 검증]
    B --> C[기후 · 소비반응 분석]
    C --> D[감소위험 분류<br/>시간순서 평가]
    D --> E[취약상권 산출]
    E --> F[3대 보호정책]
```

**핵심 결과**

- 폭염 · 호우 · 한파 · 대설이 **전체 매출을 일관되게 감소시킨다는 근거는 확인되지 않았습니다.** 대신 *평균 안에 가려진 차이*를 찾았습니다 — 고령층의 소비시간 변화, 강수시간대 일부 업종의 결제감소 위험, 반복 침수지역의 공간 노출
- 서울 **1,568개 상권** 중 2022~2025년 침수흔적이 있는 798개를 대상으로 노출 · 민감도 · 영향규모를 합산해 **현장 우선점검 후보 160개**를 선별 (법정 위험등급이 아닌 분석 후보)
- 시간순서로 평가한 결제감소 위험 분류에서 기상 모형은 기준 모형보다 개선 — **ROC-AUC 0.629 → 0.672**, 상위 10% 정밀도 **40.4% → 44.8%** (강수시간대 54.6%)
- **인터랙티브 3D 침수지도**(단일 HTML, `deck.gl`)로 지형 · 하천 · 연도별 침수흔적 · 자치구별 상권규모를 탐색

**정책 제안:** 상인 · 소비자 · 점포를 함께 보호하는 3가지 — ① 간호인력이 포함된 **기후취약상인 건강안전망** ② 폭염 · 한파 특보 시 병원 이동을 돕는 **의료동행 모빌리티** ③ 호우예보와 연동한 **공동형 이동식 차수체계**. 의료 현장 경험이 정책 설계의 출발점이었습니다.

**엔지니어링 포인트**
- 전처리 → 탐색 → 통계 검증 → 모델 → 시각화로 이어지는 **번호순 분석 스크립트 약 40개**, 원본 데이터는 수정하지 않고 전처리 자료는 코드로 재생성
- 데이터 품질 점검(범위 · 결측 · 중복), **데이터사전 · 재현 실행 가이드 · 외부데이터 출처 문서** 작성
- 제출 묶음의 파일별 SHA-256 기록과 ZIP 무결성 검수
- 공간분석(`shapely` · `pyproj` · `pyshp`)으로 침수도형과 상권 경계를 중첩

**정직한 한계:** 카드 소비반응은 강남구 · 춘천시 자료로만 학습해 **서울 전역의 피해확률이 아닙니다.** 강수시간대의 실제 감소율(43.85%)보다 예측확률(평균 26.13%)이 낮아, 예측값은 *보정된 확률이 아니라 우선점검 순서를 정하는 참고값*으로만 사용했습니다. 기상만의 인과효과로 단정하지 않았습니다.

**내가 한 일:** 분석 설계 · 데이터 전처리 · 통계 검증 · 예측모형 · 3D 지도 · 정책 제안 · 발표자료 제작

> 🔐 대회 제공 신한카드 · SK 통신 자료는 대회 목적 밖으로 공개하지 않아, 원본 데이터와 코드는 이 포트폴리오에 포함하지 않았습니다.
